2026-10-24 拍。頁面是 threads.com 上一則公開串（@zuck 的貼文），用 Felix 本機**已登入**的 Chrome 開，淺色模式，視窗 1458×787。

## 這組截圖怎麼來的

- **真的**
  - threads.com 頁面本身，以及登入狀態。
  - 擴充套件的畫面程式：`lib/engine.mjs` 和 `content.css`，跟套件裡是同一份。
  - 帳號背景的兩個 Threads 請求，以及讀回來的加入年月和所在地點。
- **模擬的**
  - Whospost 清單：三個帳號，分別 4 項、3 項、1 項符合。
  - 即時查的回應：查詢中 → 快篩 2 項 → 完整 4 項，由注入工具依序切換。
  - 沒有送任何請求到 Whospost。
- **怎麼跑起來的**
  - 擴充套件不是從 chrome://extensions 安裝的。截圖工具把 engine 注入頁面，storage 換成記憶體版，背景程式的節流和自動暫停規則用同一份 `lib/profile.mjs` 重建。這個工具沒有進 repo。
- **遮蔽**：頁面上所有帳號名稱換成 user01、user02…，頭像換成灰色。右側欄的「Mark Zuckerberg」是貼文作者本人的公開資訊，沒有遮。

## 沒拍到、未驗證的

- **用安裝好的擴充套件在登入頁跑完整流程**：未驗證。這組是注入同一份 engine 拍的。安裝路徑由 CI 的 fixture e2e 驗：Playwright 載入 `extension/`，跑在 threads.com 網址下的 fixture 頁。
- **滑過名字時出現的「即時查」按鈕**：沒有截圖。滑過名字也會跳出 Threads 自己的名字卡片，上面是對方的真實顯示名稱、自介和粉絲數，不適合放進 repo。功能本身在這次操作中有出現，04 就是按了它之後的畫面。
- **「新帳號」灰標**：真實頁上沒有符合條件的帳號（加入未滿 60 天，且本串則數夠多或在清單上），未在真實頁驗證。fixture e2e 有斷言，畫面在 CI 的 `f9-profile-line.png`、`f10-profile-popover.png`。
- **「帳號背景暫停」pill**：未在真實頁驗證，因為不能叫 Threads 真的拒絕。fixture e2e 用 403 模擬並斷言。
- **即時查失敗、每小時上限**：未在真實頁驗證，由 fixture e2e 斷言。
- **彈出視窗**：這組沒拍；0.1.0 的彈出視窗截圖在 `../ui2-4-popup.png`，帳號背景開關那段未截圖。
- **深色模式**：這組是淺色。10-24 曾在深色模式下確認浮層標題看得清楚（修了 Threads 的 `h4` 顏色蓋掉標題的問題），那張沒放進這組。
